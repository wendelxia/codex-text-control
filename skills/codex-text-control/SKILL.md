# Codex Text Control（Codex 文本控制）

## 普通对话直通

除下述明确触发条件外，用户没有要求修改文字时按普通 Codex 对话处理。不打开画布、不保存版本。像“继续”“好的”“解释一下”“正常聊聊”这类普通对话保持原体验。

当前文存在正在讨论的回复、文字、规则或上下文时，“我来改下”“我自己改一下”“让我改”“我改改”表示用户要亲自编辑，必须打开画布。不要只看“改”字触发；“我来改代码”“我改天再说”“我已经改完文件了”分别属于代码任务、时间安排和已完成操作。

## 打开上下文画布

每次调用任何 MCP 工具都必须显式传入 `projectDir`，值为当前工作区根目录。不得省略 `projectDir`；省略时旧版本会把插件安装目录误当成项目，新版本会直接拒绝。用户指定了其他项目路径时，使用用户指定的项目根目录。

用户说“打开上下文画布”“直接改上下文”“修改上下文里的表格”“删掉或增加上下文文字”时：

1. 先调用 `get_authoritative_context`，传入当前工作区根目录，读取当前权威内容。
2. 调用 `render_text_control_widget`，继续传入同一个当前工作区根目录。已有权威内容时不必重复传入全文；用户明确要编辑刚生成但尚未保存的回复时，才把该完整回复放入 `sourceText`。
3. 画布默认使用一个连续的多行正文编辑器，完整 Markdown（包括表格）不拆成文字块、单元格或行号视觉结构；复杂语法可以切换“源码”视图。
4. 用户修改时，Widget 只保留当前画布内的本地草稿，不调用写工具，也不把中文输入法中间态写入历史版本。
5. 用户完成本轮编辑时点击常驻控制条里的“完成编辑”；Widget 先弹出完整待提交原文供最后检查，此时不调用写工具。用户点击“确认提交”后，Widget 才调用仅应用可见的 `update_authoritative_context`，一次完成不可变修订和权威指针更新，再只向对话回传一次最新版本号，不重复全文。模型不能代替用户调用写工具。

初次打开、编辑过程和提交前检查都不保存。只有用户实际修改连续正文或源码，点击“完成编辑”并在完整原文检查弹窗中点击“确认提交”后，才保存和更新权威版本；点击“返回修改”会保留当前草稿。未修改直接关闭不会生成版本，未完成的本地草稿关闭后也不承诺恢复。

## 画布更新后的必做动作

收到下面格式的用户消息时：

```text
【上下文画布已更新】
版本：rev-...
```

必须先调用 `get_authoritative_context`，显式传入当前工作区根目录，读取磁盘上的当前权威正文，再继续回答。不得凭聊天里较早的全文猜测，不得要求用户粘贴全文，也不得在回复里复述整份上下文。只需简短确认已采用哪个版本；除非用户明确要求展示，否则不输出全文。

## 结论稿自动进入画布

当模型准备发送的完整最终答复本身是用户后续会继续采用或修改的结论稿时，即使用户没有明确说“编辑”，也调用 `render_text_control_widget`，传入当前工作区根目录，并把完整最终答复原样放入 `sourceText`。自动进入画布时，必须先完成整份最终稿，再调用工具；不得在草稿尚未完整时提前调用。以下情况触发：

- 把一段讨论、零散想法或多份信息整理成结论、决策、需求或共识。
- 提出用户可继续采用或修改的建议，或给出推荐方案、执行计划、规则、优先级或验收标准。
- 将用户的意图重组为可直接继续使用的完整文本，而不只是回答一个问题。

判断“回复正文是否值得成为后续上下文”，不要判断它有没有表格、连续编号或足够长。不要求建议很长或已经成体系；只要完整最终回复的主要内容是用户可继续采用或修改的建议，就应触发。随手附带的一句提醒仍按简短对话处理；表格或连续编号不能单独触发。

以下情况不自动打开画布：

- 本轮主要产物已经生成、修改或交付到代码、文件、文档或外部系统；最终回复只是交付说明，即使包含总结、表格或编号也不触发。
- 简短对话、单点问答、确认、解释、进度汇报、澄清问题或状态说明。
- 命令输出、日志、报错、代码块、工具返回、引用材料或用户输入。

只判断完整最终回复，工作过程中的进度消息不得触发。同一份最终稿最多调用一次 `render_text_control_widget`，不得重试生成第二个相同画布；工具成功返回后立即停止本轮，不再发送普通最终回复，也不得在聊天中复述画布全文。不得用空画布探测当前上下文；探测只能调用 `get_authoritative_context`。初次打开、编辑过程和提交前检查都不保存；用户在画布中实际修改、检查完整原文并点击“确认提交”后才保存和更新权威版本。

## 命名 AI 扩展点

扩展点仍使用唯一、不嵌套、独占一行的标记：

```text
【AI扩展点：发布门槛】
这里是允许 AI 补充的内容
【/AI扩展点】
```

用户要求“只补充扩展点‘发布门槛’”时：

1. 先调用 `get_authoritative_context`，传入当前工作区根目录，确认名称存在并理解附近固定要求。
2. 只生成扩展点内部的候选文字，不润色、压缩或重排扩展点外正文。
3. 调用 `render_text_control_widget`，传入当前工作区根目录、`extensionPoint` 和块内 `extensionText`，不传完整 `sourceText`。
4. Widget 只显示块内源码；用户点击“完成编辑”后先检查完整块内原文，点击“确认提交”后才通过受限工具保存并更新，后端从基准权威版本重建全文。
5. `extensionText` 不能包含扩展点起止标记。权威版本变化、重名、嵌套、孤立或未闭合时必须拒绝。

## 约束

- 不修改 Codex 内部会话数据库或 JSONL 历史。
- 版本文件位于项目 `.codex-text-control/`，不是插件安装目录。
- Markdown 是磁盘权威格式；画布是编辑视图，源码视图是复杂语法的恢复通道。
- 用户和模型文字只按纯文本进入 DOM，不作为 HTML 执行。
- 旧的 `save_text_revision` 与 `commit_authoritative_context` 继续兼容，但新画布主流程不显示两步按钮。
- 相同正文复用已有修订；过期基准必须拒绝，不能覆盖并发修改。

## 验收

- 连续正文和 Markdown 表格可直接编辑并一次全选、复制或粘贴；界面不提供逐块、单元格、行号或其他结构工具，结构变化直接在同一正文或源码视图中修改。
- 输入、停顿、输入法组合和提交前检查期间不调用写工具；检查弹窗逐字显示完整待提交原文，点击“确认提交”后只调用一次画布更新工具，并显示新版本号。
- 画布正文在组件内部滚动，顶部视图和工具控制条在长文编辑时保持可见；用户确认提交后才发送一次不含全文的通知，模型收到后读取最新版。
- 完成保存期间锁定编辑控件；超时后恢复操作，本地内容不丢失。
- 超时、通知失败和并发冲突时，本地编辑内容仍保留且提示准确。
- 历史版本可载入，旧修订不被覆盖；扩展点外正文逐字不变。

## 客观评价

画布减少了聊天反复复制全文的问题，同时让 Markdown 表格和其他正文保持同一份可全选原文，并保留版本追踪与源码恢复。限制是画布不提供表格预览、单元格级格式化或差异视图；复杂语法应在源码视图核对。Codex 仍不能原地改写历史消息，版本通知是新的简短用户消息。
