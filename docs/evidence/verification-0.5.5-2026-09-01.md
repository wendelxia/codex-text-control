# 0.5.5 正文原位编辑候选验证记录（2026-09-01）

## 用途、输入和输出

本文件记录 `0.5.5+codex.20260901100013` 对“点击正文时出现横向文字框”的修复证据。输入是用户的真实体验反馈、0.5.4 页面、冻结回归测试和 Chromium（浏览器内核）真实 DOM；输出是样式变更、自动化结果、桌面与窄屏截图、安装一致性和候选判定。

依赖 Windows、Node.js 22 或更高版本、npm、Chromium 和 Codex MCP Apps（MCP 应用）桥接。限制是普通 Chromium 不能代替完全重启后的 Codex 真实宿主；当前也没有适用于上下文画布的外部权威能力基准。

## 边界、数据流和失败恢复

- 只改变普通正文块的悬停与焦点外观，不改变文字输入、Markdown 序列化、保存工具、修订格式或权威指针。
- 用户点击正文后，浏览器把焦点交给原有 `textarea`，正文四边框和轮廓不绘制，只由父块伪元素显示左侧 2 像素短竖线。
- 源码编辑器和表格单元格继续使用完整焦点轮廓，避免丢失明确的编辑边界。
- 若新样式导致可访问性、窄屏溢出或宿主显示异常，可重新安装 0.5.4；数据格式没有变化，不需要迁移。

## 测试驱动证据

第一次回归测试冻结了“普通正文无四边框、无通用输入焦点框、保留非矩形提示”。旧样式先稳定失败，最小实现后通过。普通浏览器截图随后发现父块内阴影仍画出横线，因此扩充测试，明确禁止整行 `box-shadow`，要求使用独立竖线伪元素；扩充后的测试在旧实现上再次稳定失败，修改后通过。

完整候选门槛结果：自动测试 `48/48`、JavaScript 语法检查和 MCP 闭环探针全部通过；npm 官方注册表报告生产依赖已知漏洞 `0`，`96` 个包签名和 `11` 个来源证明通过。同一候选连续运行完整测试 10 次，共 `480` 项断言，失败运行 `0`，观察到的不稳定率为 `0/10`。

技能校验脚本第一次受 Windows 默认 GBK 编码影响而无法读取 UTF-8 文件，这次结果无效；显式设置 `PYTHONUTF8=1` 后，官方 `quick_validate.py` 返回 `Skill is valid!`。这说明技能文件本身通过校验，也说明 Windows 复现命令必须明确 UTF-8 环境。

## 已证实、未证实、失败与限制

### 已证实

- 普通正文点击时不再出现横向矩形框、下划线或整行阴影。
- 桌面和 320 像素窄屏都保留左侧短竖线，没有页面横向溢出。
- 表格和源码的焦点边界没有被一并删除。
- 完整候选门槛、10 次重复运行和技能结构校验通过。
- 插件列表显示 `0.5.5+codex.20260901100013` 已安装并启用；安装副本的 `48/48` 测试与语法检查通过。
- 源码与安装副本各有 71 个交付文件；缺失 `0`、额外 `0`，逐文件 SHA-256（文件指纹算法）差异 `0`。

### 未证实

- 尚未在完全重启后的 Codex 宿主确认最终绘制效果。
- 尚未由独立维护者复核，也没有跨平台和第二台设备证据。

### 失败与限制

- 第一次样式方案虽然通过源码断言，但真实截图仍出现横线，已判为失败方案并由第二轮测试阻断。
- 补录证据后尝试覆盖同名安装缓存时，Windows 因目录占用拒绝备份；该次安装结果作废，最终候选改用新的唯一构建号安装到独立目录。
- 当前缺少外部权威验证，不能声称能力领先同类项目。
- 0.5.4 的未保存草稿限制、跨进程锁缺口和公开发布阻塞仍然存在，本次没有扩大范围处理。

## 候选判定与回退

0.5.5 只能在自动化、普通浏览器、安装一致性全部通过后标记为本地候选。完全重启 Codex 后仍需真实点击普通正文，确认没有横向框或横线，编辑与完成保存正常，才能补充真实宿主证据。

如复验失败，重新安装 `0.5.4+codex.20260901093654`。修订文件、权威指针和 MCP 工具协议没有变化，回退不需要迁移或删除项目数据。
