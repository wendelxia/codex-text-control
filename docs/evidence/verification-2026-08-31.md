# 0.2.1 验证记录（2026-08-31）

## 用途

本文件保存候选版本的原始检查口径。输入是源码和锁定依赖，输出是测试、协议探测、安全审计与真实宿主状态。它不是第三方认证，也不能替代用户验收。

## 固定环境

- 操作系统：Windows，PowerShell。
- Node.js：本机 `v24.16.0`，并用 Node 22 兼容运行时复核测试与 MCP 探测。
- Python：`3.11.2`，只用于插件清单校验，不参与运行时。
- npm 依赖：由 `package-lock.json` 锁定。
- 安全数据源：`https://registry.npmjs.org/` 官方漏洞和签名接口。

## 失败项

- 第一次真实宿主验收失败，界面明确显示“Codex 应用桥接未加载”。根因是 HTML 字符串替换把第三方 SDK 中的 `$&` 展开成 `</head>`，造成脚本语法损坏；修复后在完整重启的真实宿主中未再出现。
- 第二次真实宿主验收失败，错误为旧 `0.2.0` MCP 进程读取已被升级安装器清空的旧缓存路径，导致 `resources/read` 报 `ENOENT`。改为启动时把 Widget 放入内存并完整重启后，真实宿主未再出现该错误。
- 第三次恢复与幂等验收曾失败：Codex 复用同一个 Widget 实例时，新的打开请求因为正文框非空而没有装载指定的第 1 版，用户实际再次提交了第 2 版。失败修订 `rev-1788170304426-bee3279f` 继续保留。增加唯一 `renderId`（渲染编号）后，本地回归测试和完整重启后的真实宿主复验均已通过；正确权威指针已恢复，重复提交也没有新增修订。
- 首次真实修订的 `note`（修改说明）为空；随后输入的“0.2.1 真实宿主验收”出现在第 2 版正文第一行末尾。当前不能证明修改说明输入流程足够不易混淆。
- 当前源码开始本轮前不是 Git 仓库，也没有 CI、根许可证和变更记录；本轮已补文件，但线上 CI 仍要在 GitHub 推送后才有证据。
- 插件清单曾声称“查看版本差异”，实际只有历史载入；本轮已修正文案，真正 diff 仍未实现。

## 限制和客观评价

在本机 Windows、当前 Codex 版本和当前用户的核心流程范围内，证据等级达到“可用”：真实用户已经完成编辑、保存、提交、错误版本恢复、关闭重开恢复和同版本重复提交，失败时也出现过明确错误且修复后可以恢复。这个结论不外推到其他设备、其他操作系统或其他 Codex 版本。

项目整体仍未达到“可发布”：第二台干净设备复现、线上持续集成（Continuous Integration，CI）、跨平台真实宿主、完整无障碍检查和独立安全审计仍缺证据。自动化检查和本机真实闭环比若干低关注度直接同类更扎实，但这不是权威横向基准，也不能据此声称领先同类。
