# 0.5.11 混合 Widget 载荷验证记录（2026-09-03）

## 用途、输入和边界

本文件记录 0.5.11 修复的画布串线问题：复用的 Codex Widget（小组件）可能先收到新标题，再收到旧正文或暂时缺少正文；服务端也曾允许只传自定义标题而不传本轮候选正文，导致新标题套到旧权威正文或旧草稿上。输入是 `mcp/server.mjs`、`ui/editor.js`、Widget 交互夹具、MCP 契约测试和当前 Node.js 环境；输出是回归测试、完整测试、语法检查、MCP 探针和供应链检查结果。

这份记录证明客户端对部分宿主载荷的处理，不证明所有 Codex 宿主都不会产生其他类型的数据串线，也不提供跨平台真实宿主矩阵或外部权威可用性基准。

## 根因和修复

- 根因：`loadData()` 在判断新 `renderId`（渲染编号）和正文是否完整前，就先应用标题；标题-only 载荷因此可以推进标题，而正文仍保留旧状态，并且 render ID 也可能提前推进。另一条服务端入口允许“自定义标题 + 省略候选正文”回退到旧权威正文，形成截图中的新标题旧正文。
- 修复：客户端先计算本次载荷的完整正文；新渲染或首次载荷缺少正文时整包忽略。服务端拒绝缺少 `sourceText` 的自定义标题渲染。只有正文存在时，才一起应用标题、模式、正文和渲染编号。
- 回归测试：模拟旧完整渲染、部分新渲染、同一新渲染编号下补齐正文，断言中间状态不串线，补齐后标题和正文同步更新；同时覆盖已有旧权威正文时，自定义标题但缺少候选正文会被 MCP 合约拒绝。

## 客观结论

0.5.11 已通过自动化、协议、语法和供应链检查，并有针对用户报告串线现象的失败回归测试。当前证据支持“部分 Widget 载荷和缺正文的自定义标题调用不会再把新标题和旧正文拼在一起”；仍不能写成生产可用、跨平台兼容或外部权威基准领先。
