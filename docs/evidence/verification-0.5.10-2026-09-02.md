# 0.5.10 草稿持久化与最近正文验证记录（2026-09-02）

## 用途、输入和边界

本文件记录 0.5.10 在 0.5.9 连续正文画布上增加的草稿持久化、跨对话恢复、权威版本冲突保护和“只返回最近正文”改动。输入是当前工作树、项目内 `.codex-text-control/` 存储、Widget 交互夹具和 MCP 客户端契约；输出是可重复的自动测试、语法检查、MCP 探针和供应链检查结果。

测试依赖 Node.js 22 或更高版本、npm 和本地文件系统，不依赖外部服务。自动化夹具不能代替完全重启后的 Codex 真实宿主，也没有跨平台视觉回归截图；因此本记录不把源码测试写成真实宿主验收。

## 行为变化

- 编辑停顿、页面隐藏和切换对话时尽力把当前正文写入项目内 `drafts/`，草稿不进入正式修订历史。
- 草稿保存请求串行执行；编辑版本号变化时，旧请求结果不能覆盖新正文。
- 打开画布时，基线未变化的草稿可以恢复；基线已变化时只显示当前权威正文，并提供用户主动载入、核对后再提交的路径。
- 输入法组合态不会写入中间文本；恢复当前权威版本会清理对应磁盘草稿。
- `get_authoritative_context` 默认返回最近 12,000 个字符，并标明是否截断；画布内部仍读取完整正文。

## 人工验收结果

用户已完成重新安装并完全重启 Codex 后的真实宿主复验，并报告以下路径通过。本次会话没有自动采集宿主截图、控制台日志或独立录像，因此这些条目是用户报告的当前环境证据，不外推到其他宿主或操作系统：

1. 编辑停顿后切换到另一个对话，再打开同一项目，草稿能恢复且未生成正式版本。
2. 权威版本在草稿期间发生变化时，画布显示新权威正文；只有点击“载入冲突草稿”并核对后才允许提交。
3. 中文输入法组合态中关闭画布不会把中间字符串写入草稿。
4. 点击“恢复当前版本”后重新打开画布，之前的草稿不再出现。
5. 超长权威正文通过 `get_authoritative_context` 返回最近文本并带有截断标记，画布仍能显示完整正文。

## 客观结论

0.5.10 已在当前机器上完成自动化、协议、供应链候选检查，并由用户完成真实 Codex 宿主复验；新增竞态和恢复路径有回归测试。由于没有跨平台宿主矩阵和外部权威可用性基准，本版本仍作为公开预发布版，不能称为稳定版或生产可用版。
