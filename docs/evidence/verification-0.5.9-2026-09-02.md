# 0.5.9 连续正文画布验证记录（2026-09-02）

## 用途、输入和输出

本文件记录画布从逐块/单元格视觉结构改为单一连续 Markdown 文本流后的工程验证。输入是当前工作树、Widget 交互测试夹具和包含 Markdown 表格的正文样本；输出是测试结果、实现边界、失败恢复说明和真实宿主待验收项。

依赖 Node.js 22 或更高版本、npm 和本地仓库。测试使用 Node.js 内置测试运行器与仓库现有的 MCP（模型上下文协议）夹具，不依赖网络服务。限制是自动化夹具不能代替完全重启后的 Codex 真实宿主，也没有跨平台视觉回归截图；本轮尝试通过本地 HTTP 预览做浏览器检查时，已占用端口和浏览器本地 URL 白名单阻止了页面加载，因此不把该项记为通过。

## 变更边界

- 画布只保留一个 `textarea#canvas-editor`，正文、段落和 Markdown 表格共享同一个字符串。
- 画布不再渲染逐行前缀、块边界、表格单元格输入框或行号式视觉结构。
- “源码”视图仍保留，用于复杂 Markdown 的原文核对；两个视图切换时只复制字符串，不解析和序列化正文。
- 提交前检查、确认提交、不可变修订、权威指针、通知、并发保护和扩展点协议不在本次变更范围内。

## 人工验收清单

在重新安装并完全重启 Codex 后，必须逐项确认：

1. 画布中只有一个正文编辑区域，点击后 `Ctrl+A` 能一次选中全文。
2. 复制全文包含所有段落和 Markdown 表格原文；页面没有左侧行号、逐行前缀或独立单元格输入框。
3. 画布与源码视图切换后内容逐字一致，编辑表格不会自动重排其他正文。
4. 点击“完成编辑”时弹窗显示完整原文；“返回修改”不写盘；“确认提交”只生成一次权威更新和一次版本通知。
5. 保存超时、桥接断开或权威版本冲突时，本地连续正文仍保留且控件恢复可操作。

## 客观评价

本次改动直接解决了用户无法整段选择、复制和编辑正文的问题，降低了画布的视觉和状态复杂度。当前证据覆盖源码、自动化 Widget 夹具、MCP 探针和 npm 供应链检查；在新构建完成真实 Codex 宿主点击闭环、窄屏布局和跨平台复验前，只能作为公开预发布版，不能声称达到稳定版或生产可用门槛。
