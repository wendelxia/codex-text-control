# 0.5.3 结论稿触发候选验证记录（2026-09-01）

## 用途

本文件记录自动触发规则从格式判断改为结论稿判断的证据。输入是 Codex 准备发送的完整最终回复；输出是触发或不触发上下文画布的路由决定。依赖 Codex 技能路由和现有 `render_text_control_widget`，不修改画布、修订存储或权威指针格式。当前没有适用于此类自然语言路由的外部权威基准，因此只能报告内部契约和待完成的真实宿主验收。

## 冻结边界

应触发：整理讨论或多份信息后的结论、决策、需求、共识，以及成体系的建议、方案、计划、规则、优先级和验收标准。

不应触发：主要产物已经生成或修改到代码、文件、文档或外部系统的交付回复；简短对话、单点问答、确认、普通解释、进度、澄清、状态、命令输出、日志、报错和代码块。

表格、编号和长度既不是充分条件，也不是必要条件。只判断完整最终回复，工作过程消息永不触发。自动打开本身不保存；只有用户实际修改后才生成新修订。

## 已证实

- 新增契约测试在旧技能上稳定 2/2 失败：旧 YAML 描述没有结论稿语义正例，也没有文件交付和简短对话反例。
- 修改后聚焦路由测试 7/7 通过；关键正反条件同时写入技能 YAML 描述，正文提供一致的执行边界。
- 使用技能创建器提供的 `generate_openai_yaml.py` 更新界面元数据；第一次受 Windows GBK 默认编码阻止，启用 Python UTF-8 模式后成功。
- 使用 `quick_validate.py` 校验技能目录，结果为 `Skill is valid!`。

## 未证实

- 契约测试只证明路由说明存在且一致，不能证明 Codex 宿主一定正确理解每一种自然语言回复。
- 尚未完全重启 Codex 验证无编号建议、讨论总结能自动打开，也未验证带编号的代码交付说明和简短问答不会打开。
- 尚未由另一模型、第二台设备或另一位用户独立复核；当前缺少外部权威验证，不能声称路由准确率领先。

## 失败与限制

- 第一次官方元数据生成因 Python 按 GBK 读取 UTF-8 技能而失败，未写入文件；同参数启用 UTF-8 后通过。
- 自然语言“结论稿”存在边界案例，例如很长的解释或文件交付后附带新的战略建议。当前规则优先避免打断文件与代码交付；用户仍可明确说“打开上下文画布”覆盖自动判断。

## 下一步与客观评价

完全重启后至少验证一个无表格、无编号的建议正例，一个讨论总结正例，一个带编号的文件交付反例和一个简短问答反例，再完成一次编辑、静默保存和单次通知闭环。0.5.3 的方向比格式触发更符合真实需求，但在上述真实宿主证据完成前仍是候选版。
