# 0.3.0 AI 扩展点候选验证记录（2026-08-31）

## 用途

本文件记录“固定正文 + 命名 AI 扩展点”的候选验证。输入是用户提出的真实问题、旧权威上下文、扩展点名称和 AI 块内候选文字；输出是受限修订、权威指针和对话回传消息。它不是第三方认证，也不能用自动测试或普通浏览器代替真实 Codex 宿主。

## 冻结目标和协议

- 扩展点标记：独占一行的 `【AI扩展点：唯一名称】` 与 `【/AI扩展点】`，不允许重名或嵌套。
- AI 输入：读取当前权威正文，只生成指定扩展点内部的 `extensionText`（扩展文字）。
- Widget 输入：扩展点名称、块内候选文字、基准权威版本号；扩展模式不接收客户端提交的完整新正文。
- 后端输出：从基准权威修订重建的完整不可变快照，扩展点外正文逐字来自基准版本。
- 用户确认：模型不能保存或提交；只有 Widget 中的用户点击可以调用 `app-only`（仅应用可调用）写工具。

## 未证实

- 已完全重启并完成含扩展点基准正文的保存与提交，但尚未在真实 Codex 中完成“AI 只生成块内建议 -> 用户提交 -> 对话收到新权威版本”的后半段点击闭环。
- 尚未在真实宿主中验证块外正文的前后 SHA-256 一致；当前证据来自后端、MCP 和普通 Chromium。
- 尚未由第二台设备、另一位用户、macOS 或 Linux 独立复现。
- 尚未验证屏幕阅读器、高对比模式和线上持续集成（Continuous Integration，CI）。
- 这个小工具领域当前缺少外部权威能力基准；本文件是内部工程验证，不能声称领先同类。

## 失败项

- 用户此前把“本次修改说明”误填进正文第一行，造成错误第 2 版；`0.3.0` 已移除该字段，真实宿主基准提交中确认 `note` 为空，历史失败仍保留在旧验收数据中。
- `0.2.2` 的“我来改下”自然语言触发尚未在完全重启后的真实宿主独立验收；`0.3.0` 继承该候选规则。
- `skill-creator`（技能创建器）第一次生成界面元数据时拒绝 19 字短描述，要求 25 至 64 字；改成符合长度且不夸大能力的描述后通过。
- `browse responsive`（浏览器批量响应式截图）因其 Windows `sharp` 可选模块缺失而失败。未给项目增加无关依赖，改用 Chromium 原生视口和截图逐档验证。

## 限制和客观评价

当前证据等级是“自动与普通浏览器验证通过、真实宿主基准提交通过，但扩展点后半段闭环未完成的候选版”，不是“完整真实宿主可用”或“可发布”。扩展点外正文由后端基准重建，明显比提示词里的“请勿修改其他内容”更可靠；完整快照也保留了恢复和审计能力。

预期权威版本检查不是跨进程原子事务。当前没有跨 MCP 进程文件锁，两个进程在极窄时间窗内同时通过检查仍存在竞争风险。项目目录也尚未做工作区沙箱限制。这两项必须作为发布前安全债务处理，不能被 37/37 测试或 0 漏洞审计掩盖。

## 回退

重新安装 `0.2.2+codex.20260831185214` 可以回退扩展点功能。`0.3.0` 没有改变完整修订和权威指针的基本格式；旧版会把扩展点标记当作普通纯文本，用户数据不需要删除。
