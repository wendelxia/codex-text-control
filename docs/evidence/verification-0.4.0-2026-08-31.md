# 0.4.0 结构化答复自动编辑候选验证记录（2026-08-31）

## 用途

本文件记录“表格和连续编号答复自动进入全文编辑器”的候选验证。输入是用户请求、模型准备发送的完整最终答复及技能触发规则；输出是一次全文模式 `render_text_control_widget` 调用。依赖 Codex 技能路由和 0.3.0 的 Widget，不改变修订存储格式。当前缺少适用于此类自然语言路由的外部权威基准，因此这里只能报告内部契约测试和真实宿主待验收项，不能声称领先同类。

## 冻结目标和边界

- Markdown 表格自动进入全文可编辑模式。
- 至少两项连续编号分项自动进入全文可编辑模式，覆盖阿拉伯数字和中文数字序号。
- 完整最终答复原样进入 `sourceText`，不重复发送同一份普通最终回复。
- 日期、版本号、行内数字、代码块、终端输出、日志、用户原文和简短进度消息不触发。
- 自动打开不自动保存或提交；用户关闭编辑器后不产生修订。
- 受保护旧能力：普通短对话直通、明确编辑触发、扩展点块外逐字不变、保存提交权限边界和旧修订读取。

## 失败项

- 新增契约测试第一次运行时有 2 项失败，原因是旧技能描述和正文没有表格、连续编号与确认权规则；加入最小规则后转绿。
- `quick_validate.py` 第一次在中文 Windows 上按 GBK 读取 UTF-8 技能文件并报 `UnicodeDecodeError`；明确启用 Python UTF-8 模式后通过。该失败属于外部校验脚本的环境兼容问题，不是候选规则通过的证据，故保留记录。
- 证据文件写入后尝试覆盖同一个插件缓存版本，Codex 在备份旧缓存条目时返回“拒绝访问”。没有删除或强改活动缓存，而是按规范生成新的缓存版本路径后重装。

## 限制和客观评价

当前证据等级是“自动验证通过、最终制品已安装的候选版”，不是“真实宿主可用”或“可发布”。这次变更只修改技能路由，不触碰写权限和存储格式，改动面较小；但它的核心价值正是自然语言自动触发，所以完全重启后的真实对话验收是不可替代的晋升门槛。

## 回退

重新安装 `0.3.0+codex.20260831193635` 可以回退自动触发。0.4.0 没有改变 `.codex-text-control/` 的修订、扩展点或权威指针格式，用户数据不需要迁移或删除。
