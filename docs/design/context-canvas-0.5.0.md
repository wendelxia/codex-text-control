# 0.5.0 上下文画布冻结设计

## 用途

把上下文从“必须修改 Markdown 原文并分两步保存、提交”的弹窗，改成可直接编辑文字和表格的上下文画布。输入是当前权威 Markdown、用户在画布中的文字或表格修改；输出是新的完整 Markdown 修订、权威指针和一条不重复全文的简短对话通知。

依赖现有 MCP Apps（MCP 应用）桥接、项目内 `.codex-text-control/` 版本库和 Codex 消息回传能力。不引入云服务、数据库或新的富文本依赖。限制是首版只把常用 Markdown 结构变成可视块；复杂或无法识别的语法通过“源码”视图编辑，不假装无损支持全部 Markdown 方言。

## 目标和非目标

- 真实用户：需要长期维护项目要求、说明和表格的 Codex 桌面用户。
- 核心任务：打开当前上下文，直接修改文字或表格，停顿后自动保存为新权威版本，后续对话采用最新版。
- 当前替代方案：在大文本框中改 Markdown，再分别点击保存和提交；操作重复，表格难改，并导致对话不断重复全文。
- 成功条件：文字与表格可直接编辑；一次编辑只走一个权威更新工具；失败不丢画布内容；历史版本可恢复；对话通知不携带全文。
- 失败条件：表格修改错列、Markdown 不能恢复、模型能绕过 Widget 写入、自动保存覆盖别的并发版本、每次按键都生成版本或消息。
- 非目标：协同编辑、任意 HTML、完整办公文档排版、实时多人光标、替代专业 Markdown 编辑器。

## 数据模型

磁盘上的权威格式继续是 UTF-8 Markdown。画布解析为以下有限块：普通文本、标题、项目符号、编号、引用、代码块、空行和表格。表格保存时转回带竖线的 Markdown 表格；无法识别的行作为普通文本保留。

画布渲染只使用 DOM 节点和 `textContent`，不把用户或模型文字写入 `innerHTML`。单元格粘贴按纯文本处理。用户随时可以切换到源码视图核对和修改完整 Markdown。

## 数据流

```text
get_authoritative_context / render_text_control_widget
  -> 当前权威 Markdown
  -> 安全解析为画布块
  -> 用户直接编辑文字或表格单元格
  -> 画布块序列化回 Markdown
  -> 停顿防抖，合并连续按键
  -> update_authoritative_context（仅 Widget 可调用）
  -> 校验打开时的权威版本未变化
  -> 保存不可变修订并更新 current.json
  -> 返回新版本和简短 followUpMessage
  -> Widget 更新基准版本并继续停留在画布
  -> 用户点击“完成编辑”后，Widget 向当前对话发送一次最新版本通知
```

## 失败与恢复

- 桥接未连接：画布可查看但不写入，状态栏明确报错。
- 自动保存超时：保留当前 DOM 与源码，不清空、不回滚，显示“结果未知”，要求先重开核对历史。
- 并发版本变化：后端拒绝旧基准，画布保留本地修改，用户可复制、重开或在源码视图人工合并。
- Markdown 解析失败：退回单一普通文本块，原始字符串不丢失。
- 表格只剩一行或一列：禁止继续删除并给出可理解提示。
- 历史恢复：载入旧版本后按新的编辑操作保存，不改写旧修订文件。

## 自动保存边界

连续输入先在浏览器内合并，停顿后才调用一次后端。相同 Markdown 复用现有修订，不制造重复版本。自动保存不回传消息，避免宿主把用户从画布切回对话；用户点常驻的“完成编辑”后才回传一次最新版本通知。通知要求后续模型调用 `get_authoritative_context` 读取全文，而不是把全文再次塞入聊天。

## 需求到证据

| 需求 | 主要风险 | 测试与证据 | 晋升门槛 |
|---|---|---|---|
| 直接编辑普通文字 | 画布与 Markdown 不一致 | 解析/序列化单元测试、真实浏览器编辑 | 修改后磁盘正文一致 |
| 直接编辑表格 | 错列、转义破坏 | 单元格、增删行列、转义测试 | 表格往返后列数和内容正确 |
| 自动成为当前上下文 | 两步流程残留、覆盖并发版本 | 原子更新集成测试、过期基准拒绝 | 一次工具调用更新修订和指针 |
| 不重复全文 | 聊天继续膨胀 | MCP 返回契约测试 | followUpMessage 不包含正文 |
| 安全编辑 | 存储型脚本注入 | 纯文本 DOM 测试、内容安全策略检查 | 无 `innerHTML` 用户写入，控制台无错误 |
| 不退步 | 旧版本丢失、扩展点失效 | 全量回归、历史恢复和扩展点测试 | 所有确定性阻断测试通过 |

## 客观评价

这个设计直接解决“想改文字和表格，却被 Markdown 与两步提交打断”的问题，也减少对话全文重复。代价是需要维护 Markdown 与画布块之间的往返规则；首版不会覆盖脚注、复杂嵌套表格等全部语法，因此源码视图是必要的恢复通道，不是临时占位。
