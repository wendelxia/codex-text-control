# 架构说明

## 用途、输入和输出

本系统让 Codex 用户在排版正文中原位编辑连续 Markdown。输入是显式项目目录、候选或已确认 Markdown、权威基准版本号和用户操作；输出是可恢复草稿、用户确认的不可变完整修订和简短版本通知。保存结果是项目上下文，不改写 Codex 原生历史消息。

依赖 Codex MCP Apps（MCP 应用）桥接、Node.js（JavaScript 运行时）22 及支持原子硬链接和重命名的本地文件系统。当前界面展示可编辑段落、列表、表格和代码；不提供源码标签、插表、合并单元格或数学公式渲染，图片仅保留引用。不可变状态转换只保证共享同一项目目录的进程一致，没有跨机器分布式事务和项目目录沙箱。旧设计与版本背景见[设计索引](README.md)。

## 系统边界和数据流

```text
模型读取工具
  -> get_authoritative_context（默认最近 12,000 字符，需要前文时 fullContent: true）
  -> render_text_control_widget（传入项目目录，候选回复可带 sourceText）
  -> 一个连续 contenteditable 正文显示排版后的 Markdown
  -> 用户点击正文编辑，显示“保存”和“取消”
  -> 编辑停顿或页面隐藏时保存独立草稿；输入法组合态暂不写入
  -> 保存：锁定编辑并等待在途草稿写入，这次点击就是确认
  -> update_authoritative_context（仅应用可调用）
  -> 校验旧权威版本号
  -> revisions/<id>.json（不可变完整 Markdown）
  -> transitions/<state>.json（排他发布同一状态的唯一后继）
  -> 从 current.json 的链上检查点继续读取；编号、时间或父状态不匹配时从锚点恢复
  -> 尽力刷新 current.json（旧版本兼容缓存，不是真相来源）
  -> 清理本轮草稿，Widget 回传简短版本通知
  -> 后续模型重新调用 get_authoritative_context，按任务需要读取全文
```

扩展点走受限分支：Widget 只提交扩展点名称、基准版本号和块内文字；后端从基准全文重建新修订，块外正文不由客户端提交。

取消走另一分支：恢复编辑前正文并清理本轮草稿，不更新权威版本。初次显示候选不创建确认版本；用户可直接保存接受。相同且已确认的正文不重复保存。草稿按编辑会话记录在 `.codex-text-control/drafts/`，不加入不可变修订历史。宿主复用组件时，未完成的编辑和通知会阻止新载荷覆盖当前正文。

## 模块职责

| 位置 | 输入 | 输出 | 职责和客观评价 |
|---|---|---|---|
| `mcp/context-storage.mjs` | 项目目录、Markdown、版本号和草稿会话 | 修订、独立草稿、状态转换和兼容指针 | 完整快照易恢复；确认修订与可恢复草稿分开，状态转换不是分布式事务。 |
| `mcp/context-extensions.mjs` | 权威正文、扩展点名称、块内文字 | 只替换目标块的新正文 | 确定性限制比提示词可靠。 |
| `mcp/server.mjs` | MCP 工具请求 | 结构化结果和 Widget 数据 | 统一输入上限与应用写权限。 |
| `mcp/widget-resource.mjs` | HTML 和本地脚本 | 自包含 Widget 资源 | 启动时快照资源，避免升级回收旧缓存后报文件不存在。 |
| `ui/canvas-model.js` | 旧版 Markdown 或表格操作 | 兼容性解析结果 | 保留给历史版本和独立测试；当前连续正文画布不再用它重排用户输入。 |
| `ui/rich-text.js` | Markdown 和编辑后的 DOM | 排版正文或序列化 Markdown | 未编辑顶层块保留原文，改动块转回 Markdown；原始 HTML 禁用，图片不联网。 |
| `ui/editor.js` | 正文载荷和用户事件 | 草稿、保存请求和状态 | 管理编辑与取消、输入法状态、草稿队列、保存锁定、通知重试和宿主主题。 |
| `scripts/start-mcp.mjs` | 插件目录和锁文件 | 已加载依赖的 stdio MCP 服务 | 缺少生产依赖时按锁文件安装，禁用安装脚本，安装日志只写 stderr。 |
| `scripts/preview.mjs` | 本地浏览器请求 | 真实 MCP 存储与模拟通知 | 默认使用独立试用目录；不能作为真实 Codex 宿主通知证据。 |
| `skills/codex-text-control/` | 用户意图和版本通知 | 工具调用规则 | 规则不能保证写权限，真正权限由 MCP 元数据强制。 |

## 失败和恢复

- 桥接未连接：写控件禁用，画布状态明确报错。
- 取消编辑：等待本轮草稿队列后清理并恢复编辑前正文；清理失败时保留修改并显示错误，不伪称取消成功。
- 工具超时：保留本地输入并标记“结果未知”，用户重开后核对历史。
- 完成保存期间：编辑控件锁定，避免请求期间继续输入并产生第二个修订；结束或超时后恢复操作。
- 权威版本变化：后端拒绝旧基准并保留当前输入。恢复到旧基线草稿时先显示最新确认正文，只有用户显式载入、核对后才能按当前基准保存。
- 进程在修订写入后、转换发布前退出：只留下未提交修订，不改变权威状态。
- 进程在转换发布后退出：转换文件已经完整；后续读取沿转换链得到新状态，不依赖该进程再刷新 `current.json`。
- 多进程争用同一基准：排他发布只允许一个后继转换成功，其他进程明确收到版本变化错误。
- 旧进程延迟写回 `current.json`：读取仍从不可变锚点沿转换链计算，不会倒退。
- 检查点元数据被改写：编号、修订、提交时间和父状态必须与不可变证明一致；不一致时忽略检查点并沿链恢复。
- 状态证明被改写：重新沿链核对时明确报错，不把不一致证明继续当成权威事实。
- 通知失败：磁盘版本继续有效，界面区分“已保存”和“通知失败”；重试只发送通知，不创建第二个修订。
- Markdown 编辑：未编辑的顶层块保留原始语法，改动块可能规范化。当前界面没有源码恢复通道；复杂语法须结合保存后的 Markdown 核对。
- 插件回退：替换插件代码，不删除 `.codex-text-control/` 数据。

## 安全边界

所有用户和模型文字默认不可信。Markdown-it 使用 `html: false`，原始 HTML 作为文本；模板只接收解析器生成的 HTML，链接协议由解析器校验，图片引用被转义为不联网的文字占位。粘贴只接收纯文本。Widget 内容安全策略的外部网络、资源和 iframe 域名列表为空。正文、项目路径、版本号和扩展点名称在协议层与存储层校验。模型只可读取和打开组件，写工具是 `app-only`（仅应用可调用）；草稿写入不更新权威状态。

首次启动缺少生产依赖时会访问 npm 官方注册表安装锁定依赖。这是启动器行为，不是正文编辑视图的网络权限。更多边界见[安全策略](../../SECURITY.md)。

## 关键架构决定

### ADR-001：完整 Markdown 快照加不可变权威状态链

每个修订保存完整 Markdown；`authority-anchor.json` 固定状态起点，每个状态最多发布一个不可变后继转换。`current.json` 是可重建的链上检查点，只有状态编号、修订编号、提交时间和父状态都与 `state-proofs/` 中的证明匹配时才会采用；旧检查点仍会沿链追到最新，没有匹配证明的检查点会回退到锚点。`committed-revisions/` 防止旧修订编号被再次当成新状态，`visible-revisions/` 把内部失败候选排除在用户历史之外，`content-index/` 让正文去重不必每次扫描全部历史。相比内容补丁链，完整快照更容易人工检查和恢复；相比可回收固定锁，状态链不会因旧恢复者删除新锁而让两个写入同时进入临界区。代价是每次提交多几个很小的索引和证明文件。

### ADR-002：完成保存和版本通知替代实时回传（历史，已由 ADR-006 替代）

Codex 不能安全原地改写历史消息。真实宿主测试还证明，按停顿自动保存会把中文输入法组合态写入不可变历史。画布因此在用户点“完成编辑”时先显示完整待提交原文，只有再次点击“确认提交”才保存一次并发送最新版本号；“返回修改”不写盘并保留草稿。后续模型从磁盘读取全文。这样避免中间版本和聊天重复，同时保留明确的最终检查边界；代价是未确认就关闭的本地草稿不会写盘。

### ADR-003：Markdown 是权威格式，画布是连续文本视图（历史，已由 ADR-006 替代）

不引入专有富文本 JSON，也不把段落或表格拆成多个输入控件。画布只提供一个连续的多行文本编辑器，完整 Markdown（包括表格）按原文载入、编辑和提交；源码视图复用同一字符串作为复杂语法的核对通道。这样支持 `Ctrl+A` 全选、复制和粘贴，并避免解析/序列化造成未编辑内容的重排；代价是画布不提供单元格级格式化或可视化预览。

### ADR-004：单步权威更新

新画布调用 `update_authoritative_context` 一次完成保存和状态转换，替代界面上的“保存后提交”两步。旧工具保留兼容。同一当前状态的转换文件通过排他硬链接发布，两个不同正文的并发更新最多一个成功，另一个明确失败；多个相同正文请求只要目标正文已经成为权威内容就幂等成功。历史恢复会复制旧快照为新的修订编号，避免 `A -> B -> A` 后旧画布把第一次 A 误认成当前 A；相同恢复请求重试则复用当前恢复版本。曾评估 `proper-lockfile@4.1.2`，但其过期恢复仍是“检查旧锁 -> 删除固定路径 -> 重建”，多恢复者存在检查后再使用竞态，因此未采用。该机制依赖共享本地文件系统，不能外推为跨机器分布式事务。

### ADR-005：命名扩展点后端重建

AI 只提供块内文字，Widget 不提交可任意改写的完整新正文。后端从基准修订重建全文并拒绝异常标记，确保块外不变是代码不变量。

### ADR-006：原位排版编辑，草稿恢复与一次保存确认

0.6.0 保留 Markdown 磁盘格式与不可变确认修订，改用一个连续的排版编辑表面。Markdown-it 渲染正文，Turndown 将编辑后的 DOM 转回 Markdown；未改动顶层块直接复用原始字符串，降低无关重排。代价是被编辑块可能规范化，且没有源码标签或完整文档排版工具。

“保存”就是用户的确认动作，取代旧版二次弹窗；“取消”恢复本轮编辑前正文。停顿与页面隐藏仅写独立草稿，输入法组合态不写入，不把每次输入变成历史修订。保存后发送版本通知，后续模型按需读取确认内容。组件请求随内容增高和无边框显示，实际外框、标签与消息确认仍由 Codex 控制；该方案不能替换已有原生消息。

## 客观评价

0.6.0 将阅读与修改放在同一段排版正文中，保留项目级确认版本和受限扩展点。它仍是预发布版本：本地自动化、浏览器检查和真实 Codex 宿主是不同证据层，不能互相替代。当前原位编辑器尚未完成重启后的真实宿主点击与通知验证，跨平台宿主矩阵、网络文件系统和大文档性能也未完成验证；具体结果见[验证记录](../evidence/inline-reply-0.6.0.md)。
