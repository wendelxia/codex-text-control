# 0.5.4 完成保存与内部滚动设计

> 历史说明：本文件记录 0.5.4 时期的块/表格画布设计依据。当前实现已在后续版本收敛为单一连续 Markdown 文本流；本文件保留用于追溯“取消实时保存”和“内部滚动”的决策，不作为当前画布结构的接口说明。

## 用途、输入和输出

本文件冻结 0.5.4 的两项行为变化：编辑过程中不生成不可变修订，长正文在 Widget 内部滚动。输入是当前权威 Markdown、用户对文字、表格或源码的修改，以及“完成编辑”动作；输出是一个最终 Markdown 修订、更新后的权威指针和一条只含版本号的通知。

依赖 Codex MCP Apps（MCP 应用）桥接、浏览器内 DOM 状态、项目内 `.codex-text-control/` 版本库和 Codex 消息回传能力。编辑停顿会把草稿写入 `.codex-text-control/drafts/`，但只有确认提交才更新权威版本；页面隐藏时尽力立即写入，重新打开可恢复草稿。

## 需求来源

0.5.3 真实宿主验收中，两轮编辑合计产生 28 个不可变修订，历史包含 `yi`、`yi'j`、`fan'shang` 等中文输入法组合态。用户明确提出“不需要实时保存”。同一次验收还在长文底部记录顶部控制内容看不见，证明浏览器页面内的 `position: sticky`（吸顶定位）不能保证在 Codex 宿主外层滚动时可见。

## 边界

- 保留 Markdown 修订格式和权威指针格式；新增的草稿工具只写项目内临时 JSON，不改变正式版本协议。
- 不删除已有中间版本，也不重写历史证据。
- 不增加草稿数据库、云同步或后台常驻进程；草稿只使用项目内原子 JSON 文件。
- 不恢复“保存修订版本”和“提交权威上下文”两步流程。
- 主界面保留“完成编辑”“恢复当前版本”和仅在发现冲突时出现的“载入冲突草稿”命令。

## 数据流

```text
打开画布
  -> 读取当前权威 Markdown 和基准版本号
  -> 用户编辑文字、表格或源码
  -> 输入时只更新 Widget 本地 DOM 和脏状态
  -> 停顿或页面隐藏时尽力保存项目内草稿，中文输入法组合态不保存中间文本
  -> 草稿不进入正式版本历史，也不更新权威指针
  -> 用户点击“完成编辑”
  -> 锁定编辑控件并读取最终 Markdown
  -> update_authoritative_context 或扩展点受限保存流程
  -> 保存一个不可变修订并更新权威指针
  -> 回传一次版本通知
  -> 恢复编辑控件
```

## 布局

Widget 主区域使用稳定高度和网格布局。标题、状态、视图切换与完成按钮位于固定网格行；画布和源码面板使用 `overflow-y: auto` 在组件内部滚动。这样长文滚动不再依赖宿主外层页面是否尊重 iframe（内嵌页面）的吸顶定位。

Widget 固定向宿主申请 720 像素编辑高度，不能用当前动态视口高度反向限制自身；否则宿主首次只分配一条窄区域时，正文会被压缩到无法阅读，自动缩放也无法再把外层撑开。窄屏工具栏改为两列，避免删除“立即保存”后仍留下空列。历史面板有独立最大高度，展开时不会挤掉全部编辑空间。

## 失败与恢复

- 桥接未连接：完成按钮禁用，正文仍可查看。
- 正文为空或超出上限：拒绝保存，保留本地内容并显示原因。
- 保存超时：恢复按钮和编辑控件，保留本地内容，提示结果未知并允许重开核对。
- 并发权威版本变化：后端拒绝旧基准，本地内容保留；用户可显式载入冲突草稿，检查完整正文后再以当前基线提交。
- 通知失败：磁盘修订仍有效，界面明确区分“已保存”和“通知失败”，再次完成可重试通知。
- 未完成就关闭：不生成修订，但已写入的草稿可在同一项目恢复；页面被强制终止前的最后一次异步写入仍受浏览器生命周期限制。

## 验收门槛

| 需求 | 冻结测试 | 通过条件 |
| --- | --- | --- |
| 不保存输入法中间态 | 连续输入 `yi'j` 后停顿，再输入最终中文 | 组合态期间不保存中间文本；完成前正式版本写工具调用为 0，确认后只保存最终正文一次 |
| 表格不退步 | 修改真实表格单元格并完成 | Markdown 单元格正确，只产生一次更新 |
| 扩展点不退步 | 修改块内源码并完成 | 只调用受限扩展点保存和提交，块外不变 |
| 长文控制可见 | 在桌面和 320 像素宽度滚动画布到底部 | 视图切换和完成按钮仍可见，无外层页面长滚动 |
| 失败可恢复 | 保存永久不返回 | 超时后控件恢复，本地内容仍在 |
| 通知不重复全文 | 完成编辑 | 只发送一次版本号通知，正文不进入聊天 |

## 客观评价

完成时才更新权威版本仍保留用户主动确认边界，也避免不可变历史被输入法和停顿切碎；输入停顿产生的独立草稿解决了跨对话恢复问题。内部滚动比继续调高吸顶层级更贴合 Codex 宿主的真实嵌入方式。页面强制终止时异步保存不能绝对保证完成，因此自动保存只提高恢复概率，不冒充提交成功。
